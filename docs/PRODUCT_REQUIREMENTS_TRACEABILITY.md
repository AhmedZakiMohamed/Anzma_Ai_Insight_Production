# Anzma AI Insight Product Requirements Traceability

**Status:** Initial code-and-document audit for architecture planning  
**Audit date:** 25 November 2026  
**References:** CEO blueprints and visuals in [`product_reference/`](product_reference/README.md); current source tree and working-tree G1 slice.

This matrix compares the user-facing direction with evidence found in the repository. “Present” means a code/document foundation exists; it does not claim the feature is production-qualified. Historical verification reports are tied to their named commits/environments. The v0.2 G1 work is uncommitted and its own status document says it is not an accepted milestone.

## Status legend

- **Foundation present:** code or approved contract supports part of the behavior; do not market the whole CEO promise as delivered.
- **Working-tree slice:** uncommitted work with its own verification limitations; not an accepted release.
- **Proposed:** described in architecture/product references but not located in current runtime code.
- **Release proof required:** acceptance evidence must match a named immutable build and environment.

## Highest-value closure sequence

1. Decide launch deployment model and first real pilot/source in [`ARCHITECTURE_DECISION_REGISTER.md`](ARCHITECTURE_DECISION_REGISTER.md).
2. Agree the source connector contract and initial pilot capability manifest; keep existing ingestion contract 1.0 as Core write boundary.
3. Accept G1 only after the uncommitted slice is reviewed, migration applied in the target release path, tests rerun against that revision, and chat/UI evidence is complete.
4. Build discovery/mapping review and capability availability before expanding the list of question-specific examples.
5. Implement common result persistence/coverage, saved dashboards and reports against the same analytic result contract.
6. Resolve user identity, authorization, tenant boundary and privacy before multi-customer or person-level features.
7. Qualify alert replay, clean installation/upgrade, measured sizing, backup/restore and independent QA before customer production claims.

This sequence preserves the broad product goal while making each customer promise verifiable. The open launch-model decision does not prevent reviewing the requirement map or choosing the pilot source.
